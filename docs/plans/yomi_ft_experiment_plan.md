# 漢字の読み（特に音訓の取り違え）改善の FT 実験プラン

- 作成日: 2026-09-29
- 前提:
  - [idea_improve_yomi.md](idea_improve_yomi.md): BERT + projector をテキストだけで FT する案
  - [ベースライン評価](../reports/jkyb-parakeet_irodori-v4.1-small.md): Accuracy 93.913%、誤り 824 件
- 対象モデル: Aratako/Irodori-TTS-v4.1-Small（計 766M。DiT blocks 358M、ModernBERT-ja-310m 25層 315M、
  text projector 1.7M、duration predictor 22M）

## 要約

1. **音訓の取り違えは、トークナイザが熟語を1文字ずつに分割したときに集中している。**
   分割された熟語の中にある対象漢字は例文の 27% だが、誤りの 59%、音訓取り違えの 68% がそこで起きている（§1）。
   語彙にない熟語の読みを1文字ずつ組み立てるときに、その漢字を単独で使うときの読み（多くは訓）や、
   よく使う別の音に引っ張られている。データはこの「分割される熟語」を中心に集める。
2. **データは (漢字, 読み) ペアを単位に辞書から語を集め、例文を作る。**
   誤りの向き（音→訓、音→別の音、訓→音、送り仮名で決まる訓、同形異音語）ごとにバケットを分け、
   同じ漢字をふだんの読みで使う対照文も同数入れる（§4）。
3. **学習は「かな置換自己蒸留」を主案にする。**
   凍結した元モデルに「対象語だけひらがなにした文」を入れた出力を教師とし、
   漢字の文を入れた学生（テキスト側だけ学習し、DiT は凍結）の出力をそれに合わせる。
   外部の音声データは要らず、学習ループに ASR も入らない。
   教師信号は「凍結した DiT が正しく発音できる条件」そのものなので、idea doc の懸念
   （読みヘッドで表現を変えても、DiT がその表現を使えるとは限らない）を避けられる（§5）。
4. **最初に「かなで書けば正しく読めるか」を測る（§3 の D1）。**
   この結果がこのアプローチの上限になり、続けるかどうかの判断材料になる。

## 1. 誤りの追加分析

### 1.1 対象漢字のトークン化と誤り率

ベースラインの全 13,536 文を ModernBERT-ja のトークナイザ（チェックポイント同梱のもの）で分割し、
対象漢字を含むトークンの形で分類した。

| 対象漢字を含むトークン | 例文数 | 誤り | 誤り率 | うち音訓取り違え | 取り違えの例（`\|` はトークン境界） |
|---|---:|---:|---:|---:|---|
| 1文字トークンで、前後も漢字（熟語が分割されている） | 3,619 (27%) | 490 | **13.5%** | **156** | 従\|容、庫\|裡、蹴\|球、側\|枝、歳\|暮 |
| 1文字トークンで、前後は仮名・記号（単漢字の語） | 2,472 (18%) | 161 | 6.5% | 47 | 香\|が、上\|す、寂\|として、棟\|が |
| 複数文字のトークン（語が語彙にある） | 7,445 (55%) | 173 | 2.3% | 27 | 風車、黄金\|虫、大字、声明、敵を |
| 合計 | 13,536 | 824 | 6.1% | 230 | |

分割された熟語の中では、音読み 2,967 文の誤り率が 13.7%、付表の語 108 文の誤り率が 29.6% に上がる。

複数文字トークンで起きる取り違え（27 件）は、主に次の2種類だった。

- 同形異音語: 風車 カザ/フウ、黄金 コ/オウ、声明 ショウ/セイ、敵 カタキ/テキ、面 オモテ/メン、来る キタ/ク。
  トークンは語のとおりに切れているが、文脈で読みを選べていない。
- 助詞と漢字が1トークンになり、語の境界とトークンの境界がずれている: 「の外\|題」（外題）、
  「の幅\|員」（幅員）、「に戻\|入」（戻入）、「今\|昔の」（今昔）。

### 1.2 取り違えの向き

「同じ漢字の別の常用読みで読んだ」230 件を、正解の読みと TTS の読みの種類で分けた
（清濁・促音・長音の差は無視した）。

| 正解 → TTS の読み | 件数 | 例 |
|---|---:|---|
| 音 → 訓 | 92 | 薪炭→マキ、沼沢→ヌマ、側枝→エダ、半鐘→ガネ、大綱→ツナ、今上→イマ |
| 音 → 別の音（呉音・漢音・慣用音・唐音） | 61 | 従容→ジュウ、善男善女→ジョ、斎食→ショク、歳暮→サイ、庫裡→コ、行火→ギョウ |
| 訓 → 音 | 51 | 三角州→シュウ、大字→ジ、氏→シ、詔→ショウ、香→コウ、海幸→コウ |
| 訓 → 別の訓 | 25 | 上せる→ウワ、試みる→タメ、雌花→メス、鹿の子→シカ |
| 付表の語 | 1 | |

### 1.3 解釈

- Irodori の読みの知識は、TTS の学習音声からしか入っていない。ModernBERT の事前学習は
  テキストだけなので、読みは見ていない。学習音声にほとんど出てこない熟語は、
  1文字ずつのトークンから読みを組み立てるしかなく、その漢字のふだんの読みに倒れる。
- つまり取り違えの主因は、**分割される低頻度の熟語で読みを組み立てられないこと**と、
  **同形異音語で文脈から読みを選べないこと**の2つ。
  データもこの2つを中心に作る（§4 のバケット A〜D と E）。

## 2. 仮説

- **H1（上限）**: 誤りの多くは読みの選択の誤りで、正しい読みをかなで与えれば DiT は正しく発音できる。
  それならテキスト側（BERT / projector）の修正で直せる。
- **H2（汎化）**: 「分割される熟語」の読み方を集中的に学習すると、学習していない熟語にもある程度効く
  （例: 薪炭で「薪＋漢字→シン」を学べば、薪水にも効く）。
- **H3（過剰修正）**: 狙う読みの文だけで学習すると、読みが入れ替わるだけの過剰修正が起きる
  （薪を割る→シン）。同じ漢字をふだんの読みで使う対照文を対にして入れれば防げる。

## 3. Phase 0: 学習前の診断

### D1. かなオラクル（最優先、Go/No-go 判断）

誤り 824 文と、正解だった文から無作為に選んだ 824 文について、対象漢字を含む漢字列（語）を
かなに置き換えて生成し、`jkyb-eval tts --dataset <部分集合 JSONL>` で評価する。

- 置換: 「彼は<従>容として死に就いた。」→「彼はしょうようとして死に就いた。」。
  語の読みは JKYB の `yomi` と本文の整列で取る（助詞の「は」「へ」がワ・エになっている点に注意）。
- ひらがな版とカタカナ版の両方を試し、教師に使う表記を決める。
- 生成条件はベースラインと同じ（jvs001、seed 0、CFG などは既定値）。
- 見るもの:
  - 誤り 824 文のうち、かなにすれば直る割合を誤りタイプ別に出す。
    これがテキスト側の修正で狙える上限になる。
  - 正解 824 文がかなにしても正解のままか（教師の品質の確認）。
  - 正解 824 文について、漢字版とかな版で同じ seed の音声を比べ、韻律がどれだけ変わるか
    （対象語の区間の F0 の差など）。かな置換でアクセントが崩れるなら、学生がそれも学んでしまう。
- 判断: 音訓取り違え 230 件の大半がかなで直るなら続ける。直らないなら、ボトルネックはテキスト側ではなく
  DiT 側なので、§5.4 の S4（DiT のテキスト K/V の LoRA）や実音声を使う方向に切り替える。
- コスト: 1,648 文 × 2 表記で約 3,300 回の生成（ベースラインの速度で約 25 分）と ASR。

### D2. シードによる揺らぎ

同じ 1,648 文を seed 1 と 2 でも生成して評価する。

- 毎回間違える系統的な誤り（読みの選択の誤り）と、たまに間違える確率的な誤り
  （発音の崩れ、ASR の聞き誤り）を分ける。
- 同じ条件でのフリップ率から評価の雑音の大きさを見積もり、§6 の判定方法を決める。

### D3. 読みのプローブ（任意）

idea doc の診断。BERT の各層、projector の出力、`text_norm` の後のそれぞれで、
対象漢字のトークンから「その漢字のどの常用読みか」を当てる**線形**プローブを学習する
（学習データは §4 の独自データ、評価は JKYB）。

- 読みの情報がどこで落ちているかを見て、§5.4 でどこまで学習するかの参考にする。
- 注意: 容量の大きいデコーダ（idea doc の AR デコーダ）をプローブにすると、
  デコーダ自身が文字列から読みを学べてしまい、表現に読みがあるかどうかを測れない。
  プローブは線形にとどめる。
- S1 と S2 の比較（§5.4）でも実用上の答えは出るので、優先度は低い。

## 4. データセット設計

### 4.1 単位と語の収集

単位は常用漢字表の (漢字, 読み) ペア（4,512 組。JKYB と同じ粒度だが、例文はすべて独自に作る）。

- 語彙: JMdict と JmdictFurigana（語の中の漢字ごとの読みの割り当てがある）。
  必要に応じて SudachiDict / UniDic で補う。
- 各語の各漢字の読みを常用漢字表の読みと照合し、音・訓・熟字訓に分類する。常用外の読みは除く。
- 頻度: Wikipedia などのコーパスの出現回数。極端に低頻度の語は優先度を下げる。

### 4.2 バケット

| バケット | 狙う誤り（§1.2） | 語の例 | 選び方 |
|---|---|---|---|
| A. 分割される熟語の音読み | 音→訓（92） | 薪炭、沼沢、畳語、側枝、梵鐘、大綱 | 単独だと訓で読まれやすい漢字を含み、トークナイザで分割される熟語 |
| B. 音の種類 | 音→別の音（61） | 従容、善男善女、斎食、今上、歳暮、庫裡、行火 | 音読みを2つ以上持つ漢字で、少ない方の音を使う熟語（仏教語・古語・呉音の語に多い） |
| C. 訓読みの語、湯桶・重箱読み | 訓→音（51） | 三角州、大字、氏、詔、海幸 | 単漢字の和語、訓を含む熟語 |
| D. 送り仮名で決まる訓 | 訓→別の訓（25） | 上す/上せる/上る、試みる/試す、著す、愁える | 訓読みを2つ以上持つ漢字の動詞・形容詞 |
| E. 同形異音語 | 複数文字トークンでの取り違え | 風車、黄金、声明、人気、上手、市場、一日、敵、面 | 辞書で同じ表記に複数の読みがある語。読みごとの文を対で作る |
| F. 熟字訓・付表の語（おまけ） | 付表の語（正解率 83%） | 海女、為替、玄人、硫黄、五月 | 付表の語と JMdict の熟字訓 |
| G. 対照（ふだんの読み） | 過剰修正の防止（H3） | 薪を割る、沼に落ちる、傘をさす | A〜F の対象漢字を、その漢字の最頻の読みで使う文。A〜F と同数 |
| H. 一般文 | 全体の退行の防止 | 任意の文 | 対象漢字を特に含まない文。バッチの 20〜30% |

分割されやすさの判定には、学習するモデルと同じトークナイザを使う（§1.1 の分類がそのまま使える）。
助詞と漢字がつながるトークン（「の外」「の幅」）が出るよう、対象語の前に来る助詞もばらす。

### 4.3 優先度付け

候補の語に次の順で重みを付ける。

1. 対象漢字がトークナイザで1文字に分割される（§1.1 の誤り率 13.5% と 2.3% の差）
2. 語の中での読みが、その漢字の最頻の読み（語彙全体の頻度で重み付け）と違う
3. 頻度が中〜低（高頻度の語は複数文字トークンになっていて、たいてい読めている）
4. **実際に今のモデルが誤読する**（ハードマイニング）: 漢字の文を生成して kana-whisper で読みを確認し、
   誤読した語の重みを上げる。これが最も確実な基準で、1〜3 は候補を絞るのに使う。

### 4.4 例文の作り方

- 読みが1つしかない語: Wikipedia・青空文庫から実際の文を抜き出す。対象語の読みは辞書のものを使う。
- 同形異音語（E）と、コーパスに出てこない語: LLM に 1 語あたり 3〜5 文を作らせる。
  語・読み・意味（JMdict の語義）を与える。
  別の呼び出しで「この文の対象語の読み」を答えさせ、辞書の読みと一致した文だけ残す。
  E では、指定した読みの意味で使われているかをこの検証で確認する。
- 文の長さと対象語の位置（文頭・文中・文末）、後ろの助詞をばらす。1 文に対象語は 1 つ。
- ローカル LLM（キャッシュ済みの Qwen3.6-27B NVFP4、gemma-3-27b など）で足りるかを最初に数十語で試し、
  品質が足りなければ Claude API を使う。
- かな置換自己蒸留（§5.1）では、文全体の読みは要らない。必要なのは対象語の読みだけ。
  文全体の読みが要るのは、読みヘッドの変種（§5.5）を試すときだけ。

### 4.5 かな置換文と教師の潜在表現の生成

- かな置換文: 対象語（語全体）だけを D1 で決めた表記のかなにし、ほかは原文のまま残す。
- 凍結した元モデルで、かな置換文から潜在表現を生成する。
  - 参照音声: JVS の jvs001 以外の話者からランダムに選ぶ（今は jvs001 だけ展開済みなので、
    `data/jvs_ver1.zip` から残りの 99 話者を展開する）。一部は参照なし。
  - kana-whisper で対象語の読みを確認し、誤っていたら seed を変えて作り直すか捨てる。
- ハードマイニング用に、漢字の文からも生成して読みを確認する（§4.3 の 4）。
  漢字の文ですでに正しく読めている語は「易しい」として重みを下げる（捨てはしない）。
- G と H は漢字の文のまま生成する（かなにしない）。§5.1 で「元のモデルと同じ出力を保つ」教師に使う。
- 一般文（H）の一部には、JVS の実音声（書き起こし付き）の潜在表現もそのまま使える。

### 4.6 JKYB へのリーク対策

- JKYB の例文そのものと、n-gram が大きく重なる近似文は学習データから除く。
- JKYB を (漢字, 読み) ペアのハッシュで A・B の半分ずつに分ける。
  - **B の対象語（対象漢字を含む漢字列と、その中の語彙の語）は学習語彙から除く。**
    JKYB-B の結果は「学習していない語」への汎化（H2）を測る。
  - A の対象語は、辞書から自然に入るなら学習に含めてよい。JKYB-A の結果は「語彙を覚えた効果」を測る。
- モデルの選択（ハイパラ、チェックポイント）には独自の dev セット（学習から外した語の例文）と、
  JKYB-A から層化抽出した約 2,000 文（JKYB-A-mini）を使う。JKYB 全体と JKYB-B は最終評価で数回だけ使う。
- 独自の dev セットも JKYB と同じ JSONL 形式（`tagged_text`、`readings` など）で作れば、
  `jkyb-eval tts --dataset` でそのまま評価できる。

### 4.7 規模とコスト

| 段階 | 語数 | 文数（A〜F / G / H） | 生成回数の目安 |
|---|---:|---|---|
| パイロット | 約 2,000 | 6k / 6k / 3k | 約 2 万回（ハードマイニング込み） |
| 本番 | 2〜3 万 | 6〜9 万 / 同数 / 3 万 | 約 20 万回 |

ベースラインの生成速度（3 並列で約 2.2 文/秒、fp32、40 ステップ、3 分岐 CFG）だと、
本番の生成には約 1 日かかる。bf16 とバッチ化でどこまで速くなるかを最初に測る。
ハードマイニングは Sway Sampling で少ないステップ数に落とせるかも試す。

## 5. 学習方法

### 5.1 主案: かな置換自己蒸留

```text
教師（全部凍結）:  かな置換文 ─→ BERT_T → projector_T ─┐
                                                        ├─→ 凍結 DiT → v_T
学生:              漢字の文   ─→ BERT_S → projector_S ─┘   （同じ DiT）→ v_S
```

x0 には §4.5 の教師の潜在表現を使い、x_t = (1 − t)·x0 + t·ε とする。t は元の学習と同じ分布で引く。

```text
L = E_{A〜F} ‖ v_S(x_t, t | 漢字の文) − v_T(x_t, t | かな置換文) ‖²
  + λ_keep · E_{G,H} ‖ v_S(x_t, t | 文) − v_T(x_t, t | 文) ‖²
  + λ_dur  · E_{A〜F} | logdur_S(漢字の文) − logdur_T(かな置換文) |
```

- **CFG との整合**: テキストの無条件分岐はテキスト状態をゼロにする（`rf.py` の `text_state_uncond`）ので、
  エンコーダを変えても無条件分岐は変わらない。条件付きの速度を合わせれば、
  テキスト CFG をかけた後の速度も合う。
  ただし independent モードの話者の無条件分岐はテキスト条件を使うので、
  話者ありと話者なしの両方で蒸留する（話者ドロップアウトを入れる）。
- **正しく読めている語には勝手に効かない**: 学生と教師の出力がもともと近い語では損失がほぼ 0 になる。
  そのため、誤読している語に学習が集中する。
- **長さ**: 詔（ミコトノリ）と誤読（ショウ）では長さが大きく違う。duration predictor は `text_state`
  を読むので、凍結したまま出力を教師に合わせる項（λ_dur）を入れる。
  これはエンコーダに「読みの長さ」を持たせる圧力にもなる。
- **G・H の教師は漢字の文のまま**にする。かな置換の韻律の癖（D1 で測る）を、
  ふだんの読みの文にまで広げないため。
- 変種: 速度の蒸留の代わりに、教師の潜在表現に対する通常の RF 損失（漢字の文, x0）で学習する。
  目的は同じだが、1 サンプルごとの目標のばらつきが大きい。アブレーションで比べる。

### 5.2 テキストエンコーダがキャプションと共有されている問題

v4.1 の ModernBERT は、読み上げテキストとキャプションで**同じ重みを共有**している
（projector だけ別）。BERT を動かすとキャプション条件も変わる。

- projector だけを学習する段階（S1）では問題ない。
- BERT を動かす段階（S2 以降）では、**テキスト用に BERT を複製**し、キャプション側は元の重みのまま使う。
  もともとテキストとキャプションは別々に BERT を通しているので、推論の計算量は変わらない。
  増えるのはメモリ（パラメータ 315M 分）だけ。
- サブモジュール（Irodori-TTS）は直接いじらず、このリポジトリの側でモデルをラップして実現する。

### 5.3 duration predictor

凍結する。λ_dur の項で、学生のテキスト状態から出る長さが教師（かな置換文）の長さに合うようにする。
評価では予測された長さの分布が変わっていないかも見る（§6.3）。

### 5.4 学習範囲の段階

| 段階 | 学習するもの | 見たいこと |
|---|---|---|
| S1 | text projector（1.7M）と `text_norm` | 最小の変更でどこまで直るか |
| S2 | S1 と、複製した BERT の上位 4 層 | **本命**。下位層の一般的な表現は残し、上位層で読みを分ける |
| S3 | S1 と、複製した BERT の上位 8 層〜全層 | 自由度を上げたときの伸びと退行 |
| S4（比較） | DiT の `wk_text` / `wv_text` の LoRA（BERT は凍結） | テキスト側だけで足りるか、DiT 側の読み取りも要るか |

学習率は元の学習の設定から始める（projector 1e-4、BERT 1e-5、AdamW、ウォームアップあり）。
パイロットは数千ステップで、dev の推移を見て決める。

### 5.5 補助: 読みヘッド（idea doc の案）

projector の出力（512 次元）に線形の CTC 読みヘッド（トークンごとに数倍にアップサンプリングしてカナを出す）
を付け、G2P 損失を §5.1 の損失に足す変種。

- 主案の代わりではなく、主案に足したときに汎化（JKYB-B）が伸びるかを見る。
- D3 と同じ理由で、ヘッドは線形にとどめる（容量が大きいとヘッドだけが賢くなる）。
- 文全体の読みが必要なので、使うなら §4.4 で文全体の読みも付ける。
- idea doc の対照損失（同じ表記・違う読みの表現を離す）は、E と G の対データで同じ効果を
  データ側から入れているので、まずは入れない。

## 6. 評価

### 6.1 主指標

- JKYB の Accuracy（全体、分類別、誤りタイプ別）。条件はベースラインと同じにする
  （jvs001、seed 0、既定のサンプリング）。
- §1.1 のトークン化別の誤り率と、§1.2 の向き別の件数。`analyze_jkyb_errors.py` に集計を足す。
- JKYB-A（学習語彙に含まれうる）と JKYB-B（含まれない）に分けた Accuracy。

### 6.2 有意差の判定

同じ文・同じ seed・同じ参照音声で生成するので、ベースラインとの比較は文ごとの正誤の対応あり比較になる。
McNemar 検定を使い、D2 で測ったシードによるフリップ率も並べて書く。
最終候補は seed を 2〜3 通り変えて評価する。

### 6.3 退行チェック

- 一般文: JVS nonpara30 の文（JSUT basic5000 由来で話者ごとに違う文、100 話者で計 3,000 文）
  から約 500 文で、Whisper の CER、UTMOS、話者類似度、発話長。H の学習に使う文とは分ける。
- 対照文（G）の独自 dev: ふだんの読みが保たれているか（過剰修正の検出）。
- キャプション: BERT を複製しない変種を試すときだけ、キャプション付き生成の変化を見る。
- アクセント: 自動では測りにくいので、直った文と一般文を 20〜30 本ずつ試聴する。

### 6.4 反復のための評価コスト

JKYB 全体の評価は生成だけで約 1.7 時間かかる。反復中は JKYB-A-mini（約 2,000 文、15〜20 分）と
独自 dev で回し、JKYB 全体は段階ごとの最終候補だけにする。

## 8. リスクと対策

| リスク | 対策 |
|---|---|
| かなにしても読めない誤りが多い（D1） | テキスト側だけの方針をやめ、S4 や実音声の方向を検討する |
| かな置換でアクセントが崩れ、学生もそれを学ぶ | D1 で韻律の変化を測る。G・H の教師は漢字の文のまま。直った文を試聴する |
| 過剰修正（ふだんの読みまで変わる） | G の対照文を同数入れる。G の dev で監視する |
| 教師（かな置換文）自体の読み誤り | kana-whisper で対象語の読みを確認し、誤りは作り直すか捨てる |
| 辞書の読みの誤りや揺れ（連濁、促音化、許容読み） | 複数の読みを許容する。揺れの大きい語は外す |
| LLM が指定と違う意味で同形異音語を使う | 別の呼び出しで読みを検証し、一致したものだけ残す |
| kana-whisper の聞き誤りで評価がぶれる | D2 で雑音の大きさを測る。対応あり検定で判定する |
| JKYB への過適合 | §4.6 の A/B 分割。モデル選択は独自 dev と JKYB-A-mini だけで行う |
| 辞書・コーパスのライセンス（JMdict は CC BY-SA） | 研究用途では問題ない。重みを配布する場合は条件を確認する |

## 9. 実装するもの

すべてこのリポジトリの `scripts/` 側に置き、Irodori-TTS のサブモジュールは変更しない。

- `scripts/jkyb_kana_oracle.py`: D1 用。JKYB の部分集合を作り、対象語をかなに置換した JSONL を出す
- `scripts/build_yomi_lexicon.py`: JMdict と JmdictFurigana から (語, 漢字ごとの読み, 音訓の分類, 頻度,
  トークン化) の表を作る。バケット分け、優先度付け、JKYB の A/B 分割と除外もここで行う
- `scripts/generate_yomi_sentences.py`: コーパスからの抽出と LLM による例文生成、読みの検証
- `scripts/generate_teacher_latents.py`: かな置換文・漢字の文からの潜在表現の生成と、
  kana-whisper による検証（ハードマイニングを兼ねる）
- `scripts/train_kana_distill.py`: §5.1 の学習ループ。Irodori のモデル部品を import し、
  教師用のテキストエンコーダの複製、テキスト用 BERT の複製（§5.2）、学習範囲の切り替え（§5.4）を持つ
- `scripts/generate_jkyb_audio.py` の拡張: 学習したテキストエンコーダの重みを読み込めるようにする
- `scripts/analyze_jkyb_errors.py` の拡張: トークン化別・向き別の集計と、ベースラインとの McNemar 検定
