# サイズ削減蒸留 pilot の結果（Phase 0〜2）

- 実施日：2026-10-03
- 計画：[docs/plans/model_size_distill_plan.md](../plans/model_size_distill_plan.md)
- 教師：[Aratako/Irodori-TTS-v4.1-Small-MF](https://huggingface.co/Aratako/Irodori-TTS-v4.1-Small-MF)（773M）

## 結論（現時点）

1. **差し替え（Drop-in）は可能。** 層を間引いた ModernBERT、modernbert-ja-130m への載せ替え、層数や MLP 幅を変えた DiT、
   量子化版のいずれも、`model.safetensors` と `tokenizer/` だけで無改変の推論コードが読み込んで合成できた。
2. **text encoder は小さな劣化で削れる。**
   - T-A（310m を 12 層に間引き）は JKYB dev −0.35pt で、関門 G1 を通過した。全体の約 16% を削減。
   - T-B（130m に載せ替え）は −1.35pt で、約 24% を削減。劣化は熟字訓などの知識依存の読みに集中する。
3. **DiT は削ると品質が大きく落ちる。**
   - 9 層（DiT −24%）は Muon で 2 万ステップ学習して JKYB −4.25pt、UTMOS −0.55。まだ改善中。
   - 6 層（−48%）は崩壊した。
   - 「半分のサイズで数 pt 以内」は、今回の学習量（1 GPU、数時間〜半日）では達成できていない。
4. **VRAM の目的には「text encoder の蒸留 + 既存の int8 量子化」が最も効く。**
   - Irodori 同梱の `quantize_checkpoint.py`（int8 weight-only）は教師でほぼ無劣化だった（JKYB +0.1pt、UTMOS −0.01）。
   - T-A に int8 を重ねると JKYB −0.25pt で、常駐 VRAM は 2000→1307MiB（−35%）、8 秒発話のピークは 3074→2373MiB
     （−23%、いずれもコーデック fp32）。
   - これは DiT まで削った T-B + D9M（bf16、−9.1pt）と同じ VRAM 水準である。
5. **推論ピークの大半はコーデックの復号。** 長い発話ほど、モデル側の削減の効果は相対的に小さくなる（30 秒で −13%）。

推奨：当面の成果物は **T-A（+ int8 版）**。DiT の蒸留は、数日規模の学習を投じない限り、VRAM あたりの品質で量子化に勝てない。

## 実施内容

### Phase 0：基盤

- 評価：main の評価スクリプトを移植した。`batch_synth.py` には MF 経路を追加し、公式ランタイムとの latent の相対誤差が
  1e-5 以下になることを確かめた。
- テキスト：日本語 Wikipedia（3 シャード）から 333 万文。JKYB の文は除いた。
- 参照音声：実コーパスと、教師が作った声の2種類。
  - 実コーパス：JVNV・Hi-Fi-CAPTAIN・あみたろの 7 話者 2,715 クリップ。コーパスごとにタグを付けており、公開前にライセンスで除外できる。
  - 教師が作った声：caption だけ（参照なし）で教師に合成させた 2,000 人分。
- caption：手書きの 50 文と、属性の組み合わせで作ったもの。

### Phase 1a：text encoder の特徴蒸留（T-B）

- 教師の `text_norm(text_encoder(·))` と `caption_norm(caption_encoder(·))`（512 次元、トークンごと）、
  および duration predictor の出力を合わせた。損失は相対二乗誤差と cos。
- バッチ 128、2万ステップ、backbone lr 2e-4、projector lr 1e-3。
- 検証の相対誤差は 1.39 → 0.143（text）/ 0.141（caption）。

### Phase 2 pilot：DiT の MF→MF 出力蒸留（D6）

- 初期値は教師のブロック {0, 7, 8, 9, 10, 11}。無学習のブロック削除感度で、貪欲法が最も誤差を小さくした組。
- 1 ステップの流れ：
  1. 条件 8 件をサンプルし、教師の 4 ステップ軌道（t = 1, .75, .5, .25）と、ランダムな (t, Δ) の 8 点を作る。
  2. 生徒にその点の教師出力 u を回帰させる。
  3. 2,000 ステップ以降は半分のバッチを生徒自身の軌道の状態にした（on-policy）。
- AdamW lr 1e-4、1 万ステップ。

### その後の知見（同日）

- **caption 経路**：T-B p1a は Wikipedia の文でしか caption projector を学習しておらず、本物の声の説明文では
  caption 状態の相対誤差が 0.51 だった（文では 0.14）。毎ステップ 32 件の caption を混ぜて 6k ステップ続けた
  p1c で 0.076 になった。JKYB は −1.35pt でほぼ変わらない。
- **DiT を通した text 微調整（Phase 1b）は 2 回とも悪化した。** 勾配そのものは正しい（gradient caching と直接計算の
  cos 0.995、勾配方向の小さな一歩で損失は下がる）。ただ、損失面が text 経路のパラメータに対して非常に鋭い。
  Adam は全パラメータを毎ステップほぼ学習率ぶん動かすため、行き過ぎていると考えられる。再挑戦するなら、学習率を
  桁で下げるか、学習対象を絞る。
- **DiT の深さが品質を決める。** 同じ 1 万ステップで、6 層（DiT 52%）は JKYB 21.6%、9 層・MLP 1920（60%）は 77.7%。
- **DiT の学習レシピ**（D6、2k ステップ、ステップ別の速度場誤差）：
  - Muon（lr 2e-4）は AdamW の約 2 倍の速さで収束する。1k ステップで AdamW の 2k ステップと同じ誤差になった。
  - AdamW の lr 3e-4 は lr 1e-4 とほぼ同じだった。
  - 層ごとの隠れ状態の一致損失は効果がなかった。
- 検証の「最終 latent の教師比誤差」は、初期ステップの差で韻律などが変わるため品質と対応しない。
  ステップ別の速度場誤差を見る。

### T-A（310m を 12 層に間引き）は関門 G1 を通過

- 層 {0, 1, 2, 15, 17–24} を残し、`layer_types` を保った。テキストの特徴蒸留と caption 文で 2 万ステップ学習した。
  - 検証の相対誤差は text 0.108 / caption 0.039。T-B の 0.143 / 0.076 より小さい。
- JKYB dev は −0.35pt（直った 64 / 壊れた 71、p = 0.61）。JSUT カナ CER は +0.04pt。話者類似度・UTMOS は変わらない。
  - 付表の語は −4.7pt（150 文、p = 0.17）。T-B の −8.7pt より小さい。
- text 経路は 318M → 195M。全体では約 16% の削減。

  みている。全文（13,536 文）での確認が残っている。

### 推論 VRAM（実測、MF・model bf16）

| 候補 | 重み | ピーク 8 秒（codec fp32 / bf16） | ピーク 30 秒（codec fp32 / bf16） |
|---|---:|---:|---:|
| 教師 MF | 1475MiB | 3074 / 2561MiB | 5426 / 4489MiB |
| T-A | 1241MiB | 2831 / 2335MiB | 5183 / 4255MiB |
| T-B | 1125MiB | 2707 / 2212MiB | 5067 / 4139MiB |
| T-A + D9 | 1070MiB | 2660 / 2164MiB | 5012 / 4084MiB |
| T-B + D9M | 838MiB | 2420 / 1925MiB | 4780 / 3852MiB |

- コーデックの復号が大きいため、モデルを削っても 8 秒の発話でのピーク削減は 8〜25% にとどまる。
- `scripts/feasibility/profile_vram.py --checkpoints MF <dir>...` で測った（`outputs/feasibility/profile_vram_candidates.json`）。
  速度は学習ジョブと GPU を共有した状態の値なので載せていない。

- 半分（約 390M）にするには、DiT を 6 層程度にする必要がある。D6 は崩壊したので、今の学習量ではまだ届かない。
- DiT は「深さを保つ（9 層以上）」「MLP 幅を保つ」ほど回復が速い。D9 と D9M（MLP 1920）を比べると、後半ステップ
  （音韻の細部）の誤差は D9 の方がずっと小さい。

## 運用上の注意

- `batch_synth.py` と同じく、Irodori の SDPA は `efficient` を使う。bf16 で cuDNN を使うと、系列長ごとに実行計画を作り直して
  学習が約 3 倍遅くなる。
- DiT 学習は、長さでソートしたマイクロバッチに分けて逆伝播する（ピーク 22 GiB → 11 GiB）。text 経路を学習するときは、
  条件テンソルを葉ノードにした gradient caching を使う。
- GPU ジョブは `flock` の 2 スロットで同時 2 本までに制限する（`run_stage5.sh` 以降）。3 本重なると OOM で落ちた。
- jkyb-eval の環境は Python 3.13 で作る。3.14 では ASR の DataLoader ワーカーが pickle に失敗する。
