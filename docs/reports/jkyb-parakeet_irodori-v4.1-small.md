# Irodori-TTS-v4.1-Small の常用漢字読みベンチマーク（JKYB-Parakeet）再現試験

- 実施日: 2026-09-28〜29
- 対象モデル: [Aratako/Irodori-TTS-v4.1-Small](https://huggingface.co/Aratako/Irodori-TTS-v4.1-Small)
- 評価手法: [Parakeet 社の Zenn 記事](https://zenn.dev/parakeet_tech/articles/936532be817118) と同じ
  [JKYB-Parakeet](https://github.com/Parakeet-Inc/Joyo-Kanji-Yomi-Benchmark-Parakeet-Edition)（`jkyb-eval tts`, v0.2.0）
- 詳細な出力: [outputs/irodori-v4.1-small_jvs001/](../../outputs/irodori-v4.1-small_jvs001/)
  （`results/summary.md`, `error_analysis.md`, `error_analysis.errors.jsonl`）

## 結論

**Accuracy 93.913%** となり、記事の **93.048%** に対して +0.87pt で、「93%程度」はほぼ再現した。
他の指標もすべて記事と同程度か、やや良い値だった。

| 指標 | 記事 | 本試験 | 差 |
|---|---:|---:|---:|
| Accuracy | 93.048% | **93.913%** (12,712 / 13,536) | +0.87pt |
| Target Kana-CER@1 | 5.557% | 4.819% | −0.74pt |
| Sentence Kana-CER@1 | 1.432% | 0.908% | −0.52pt |
| Transcript (Text) CER@1 | 4.296% | 3.943% | −0.35pt |
| Relaxed Accuracy | – | 94.001% | |

読み分類別（記事には Irodori 単体の分類別の値がないため本試験の値のみ）:

| 分類 | 例文数 | Accuracy | Target Kana-CER@1 |
|---|---:|---:|---:|
| 音読み | 7,056 | 92.914% | 5.707% |
| 訓読み | 6,108 | 95.711% | 3.490% |
| 付表の語（熟字訓など） | 372 | **83.333%** | 9.794% |

記事の「G2P を持たない TTS は熟字訓の誤りが顕著に多い」という指摘と一致し、付表の語だけ正解率が約10pt低い。

## 実験設定

| 項目 | 設定 |
|---|---|
| 参照音声 | JVS コーパス `jvs001/parallel100/wav24kHz16bit/VOICEACTRESS100_001.wav`（8.6秒, 1ファイル） |
| caption | なし |
| サンプリング | Irodori の CLI デフォルト（RF Euler 40 step, CFG text=3.0 / speaker=5.0, independent, fp32） |
| 長さ | 内蔵の duration predictor で自動推定 |
| seed | 0（全文共通） |
| ASR | kana: `sbintuitions/kana-whisper`、text: `openai/whisper-large-v3-turbo`（jkyb-eval のデフォルト） |
| 環境 | RTX 5090, torch 2.10.0+cu128。3プロセス並列で合成に約1.7時間 |

記事は「ゼロショット対応モデルは JVS001 の音声を1つ与えて合成」とのみ記載しており、使ったファイル・seed・
サンプリング設定は不明。差（+0.87pt）の要因としては、参照音声の選択、seed による揺らぎ、
評価ツールのバージョン差（記事時点のデータや正規化との違い）が考えられる。
seed や参照音声を変えた複数回の試行はしていないため、ばらつきの大きさは未確認。

## 読み間違いの分析

誤り 824 件（Accuracy で不正解の行）を、`scripts/analyze_jkyb_errors.py` で次のように自動分類した。

| 誤りタイプ | 件数 | 割合 | 音 | 訓 | 付表 | うち Whisper 書き起こしは原文どおり |
|---|---:|---:|---:|---:|---:|---:|
| 許容読み（marginal）に一致（Relaxed では正解） | 12 | 1.5% | 2 | 7 | 3 | 8 |
| 生成破綻（対象の周辺が崩れている／脱落） | 12 | 1.5% | 6 | 6 | 0 | 3 |
| 清濁（連濁の有無など）の差のみ | 32 | 3.9% | 29 | 2 | 1 | 7 |
| 促音化・長音の差のみ | 81 | 9.8% | 56 | 16 | 9 | 33 |
| 同じ漢字の別の常用読みで読んだ（音訓の取り違えなど） | 230 | 27.9% | 153 | 76 | 1 | 80 |
| その他の読み誤り | 457 | 55.5% | 254 | 155 | 48 | 117 |
| 合計 | 824 | 100% | 500 | 262 | 62 | 248 |

「その他」457件のうち241件は正解と1文字だけ違うもの（例: ネバ→メバ）。
TTS の発音の崩れと kana-whisper の聞き誤りが混ざっていると考えられる。

### 1. 熟字訓・付表の語が読めない（正解率 83%）

語全体を1単位として読む熟字訓で、構成漢字を音読みしたり、崩れた読みになったりする。

| 例文（`<>` が対象） | 正解 | TTS の読み（kana-whisper） |
|---|---|---|
| 熟練の<海女>が海に潜ってアワビを獲る。 | アマ | クミジョ |
| 朝早くから<海女>たちが漁の準備を始めている。 | アマ | カイジョ |
| 伝統的な素潜り漁を行う<海士>が減っている。 | アマ | カイシ（3文とも） |
| 昔ながらの農家では、<母家>の隣に大きな蔵がある。 | オモヤ | ボバケ |
| 難しい漢字には<仮名>を振ってください。 | カナ | カメラ |
| 祖父は縁側で、盆栽の<五月>を丁寧に手入れしている。 | サツキ | ゴツツ |
| 外国<為替>市場の動向を注視する。 | カワセ | カセ |
| そのカメラは設定が細かく、<玄人>向けの機種だ。 | クロウト | クロオトン |
| 二軒目は<河岸>を変えて飲み直そう。 | カシ | カガシン |
| 温泉に行くと、<硫黄>の匂いがする。 | イオウ | イヨオ |

### 2. 同じ漢字の別の読みを選ぶ（音訓の取り違え）

漢字自体は「知っている」が、文脈に合わない読みを選ぶ。
単独で使う頻度の高い読み（訓読み／一般的な音読み）に引っ張られる傾向がある。

| 例文 | 正解 | TTS の読み |
|---|---|---|
| 鉄鉱石はしばしば<塊>状で発見される。 | カイ | カタマリ |
| 要塞の強固な壁を破壊するため、巨大な<臼>砲が投入された。 | キュウ | ウス |
| 彼は住み込みで働き、主人の<薪>水の労をとった。 | シン | マキ |
| 江戸時代の<板>本が図書館に残っている。 | ハン | イタ（イタボン） |
| 正味重量を知るためには、風<袋>を引く必要があります。 | タイ | ブクロ（カゼブクロ） |
| 日本の古典文学の中でも、今<昔>物語集は特に有名だ。 | ジャク | ムカシ |
| 台風で<棟>が損傷し、屋根瓦が飛んでしまった。 | ムネ | トウ |
| 秋の味覚を食卓に<上>す。 | ノボ | ジョウ |

### 3. 難読語・稀な読み

常用外に近い熟語や、文語的な訓読みで崩れる。

| 例文 | 正解 | TTS の読み |

| 感染拡大の<虞>から、イベントは中止された。 | オソレ | グ |
| 若者が夢を持てない社会を<愁>えるだけでは何も変わらない。 | ウレ | オシ（「教える」と読んだ） |
| 山の奥深くに大きな<洞>を見つけた。 | ホラ | トラ |
| 伝説によると、この池には巨大な<主>が住んでいる。 | ヌシ | アルシ |
| 彼は清<澄>な瞳で私を見つめた。 | チョウ | ショウ |

## 注意点

- **ASR 誤りも誤りとして数えている。** 誤り 824 件のうち 248 件は、whisper-large-v3-turbo の漢字仮名交じり
  書き起こしに対象語が原文どおり現れていた（例: 継承 → kana は「テーショー」、テキストは「継承」）。
  kana-whisper の聞き誤りの可能性があるが、Whisper の言語モデルが文脈から補正しただけの場合も多い
  （例: 女婿はカナでは「オンナムコ」、風袋は「カゼブクロ」と聞こえているのに、テキストはどちらも原文どおり）。
  音声を聴いての確認はしていないので、この 248 件は「ASR 誤りの疑いあり」の上限と見るのがよい。
- 誤りタイプの分類はヒューリスティックで、境界はあいまい（例: 棟木→トウビ は「その他」になる）。
- 結果は1 seed・1参照音声の単発試行。

## 再現手順

```bash
# 環境
(cd Irodori-TTS && uv sync --extra cu128)
(cd Joyo-Kanji-Yomi-Benchmark-Parakeet-Edition && uv sync --extra asr)
# JVS コーパスを data/jvs_ver1 に展開（再配布不可のため git 管理外）

# 合成（3 プロセス並列、shard 0..2）
PYTHONPATH=Irodori-TTS uv run --project Irodori-TTS --no-sync \
  python scripts/generate_jkyb_audio.py \
  --output-dir outputs/irodori-v4.1-small_jvs001/audio \
  --ref-wav data/jvs_ver1/jvs001/parallel100/wav24kHz16bit/VOICEACTRESS100_001.wav \
  --seed 0 --shard 0 --num-shards 3

# 評価
(cd Joyo-Kanji-Yomi-Benchmark-Parakeet-Edition && uv run --no-sync jkyb-eval tts \
  ../outputs/irodori-v4.1-small_jvs001/audio --device cuda \
  --output-dir ../outputs/irodori-v4.1-small_jvs001/results)

# 読み誤り分析
uv run python scripts/analyze_jkyb_errors.py outputs/irodori-v4.1-small_jvs001/results \
  --output outputs/irodori-v4.1-small_jvs001/error_analysis.md
```
